# RAG와 Wiki의 역할

상태: 개발 Wiki·오프라인 검색 실험 구현과 후속 서비스 설계를 구분한 요약.

## 현재 결정

원본 프로젝트 문서에서 개념·결정·미해결 사항을 정리한 Wiki를 유지한다. 목차와 출처 링크로 탐색하며 출처 해시가 바뀌면 의존 페이지를 다시 확인한다. 현재 Wiki는 법규 검색이나 답변 생성에 들어가지 않는다. 출처: [도입 설계](../../docs/llm_wiki.md).

## 후속 서비스 흐름

기존 계획은 키워드·의미 검색 → 원문 근거 입력 → 자체 모델 생성 → 인용·시점 검사다. Wiki를 실험할 때는 개념·관계에서 조문 후보 ID를 추가하고, 같은 스냅샷의 원문을 다시 조회해 문맥을 구성한다. 기준일·문서 종류·예외·경과조치 확인은 이 경로에도 적용한다. 출처: [PRD 6·7·9·10절](../../docs/FinReg_LLM_PRD_v1.md).

오프라인 도구는 BM25 원문 검색과 Wiki 후보 확장을 비교하고, 검증된 스냅샷의 원문을 재파싱해 저장 본문·위치를 대조한다. 페이지별 버전·근거·해시·검수 상태와 빌드 설정을 확인하며 Wiki가 오래되거나 참조가 깨지면 원문 검색을 유지한다. 경과조치에 추가 사실관계가 필요한 후보는 제외한다. 출처: [검색 실험 구현](../../docs/wiki_retrieval.md).

원문 제목·참조만 담은 템플릿 생성은 LLM 요약 생성이나 사람 검수가 아니다. 실제 말뭉치의 검수와 개발 평가 준비가 끝나지 않아 가상 규정으로 처리 경로를 검사했다. 임베딩 검색·RAG 답변 생성·서비스 연결은 아직 미구현이다. 출처: [검색 실험 구현](../../docs/wiki_retrieval.md).

## 채택 전에 확인할 것

동일 조건의 개발 평가에서 원문 근거 Recall@5와 다중 조문·예외 누락을 비교한다. 인용·시점 오류와 불필요한 보류의 비악화, 구축·갱신 비용과 지연을 함께 확인한다. 좋아졌다는 실측 결과는 아직 없다. 출처: [도입 설계](../../docs/llm_wiki.md).
