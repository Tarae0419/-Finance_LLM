# 검수·평가 데이터 경계

상태: 검수 정책 요약. 실제 문항이나 평가 정답을 포함하지 않는다.

## 초안과 검수

자동 생성 자료의 최초 상태는 `draft`다. 사람은 존재·의미·시점·완전성을 대조하고 정확한 리비전·근거·검수 이력을 남긴다. 외부 검토와 개발자 검수를 구분하며 외부 검토자가 없을 때의 공식 FAQ·해석자료 교차 대조 조건도 유지한다. AI가 사람의 기록을 대신 만들거나 `reviewed`로 승격하지 않는다. 출처: [검수 정책](../../docs/review_policy.md).

## 평가 분리

관련 사례·패러프레이즈·쟁점·조문 묶음으로 분할한다. 원문 법규는 검색에 쓸 수 있어도 평가 정답·해설은 검색 인덱스에 넣지 않는다. 최종 평가 질문·정답·해설은 학습·프롬프트 개선·검색 튜닝·Wiki 구축에 사용하지 않는다. 출처: [PRD 9절](../../docs/FinReg_LLM_PRD_v1.md).

E2와 E4는 같은 검색 문맥으로 비교해 미세조정 효과를 분리한다. Wiki 후보 확장의 효과는 별도 개발 실험이다. 최종 평가 결과를 보고 개선했다면 새 최종 평가셋이 필요하다. 출처: [PRD 9절](../../docs/FinReg_LLM_PRD_v1.md), [검수 정책](../../docs/review_policy.md).

## Wiki 유지 시 경계

검사기의 입력은 명시한 프로젝트 문서로 한정한다. 평가 폴더나 대화를 자동 수집하지 않으며 데이터셋 내용을 개발 문서에 옮겨 적는 것도 금지한다. 해시·링크 검사는 의미적 뒷받침이나 데이터 누출 여부를 자동 보증하지 않는다. 출처: [도입 설계](../../docs/llm_wiki.md).

별도 오프라인 검색 비교 도구는 DB에서 사람 검수된 개발 문항만 읽는다. 보고서는 ID·리비전·해시·근거 ID와 검색 지표를 남기고 질문·정답·원문을 저장하지 않는다. 검색 재현율은 답변 정합성이나 보류 행동 평가와 구분한다. 출처: [검색 실험 구현](../../docs/wiki_retrieval.md).

개발 문항의 사람 검수는 별도 로컬 화면에서 원문과 초안을 대조하며 작성할 수 있다. 작성 중 파일과 등록용 JSON을 구분하고, DB 등록 시 현재 리비전·해시·근거를 다시 확인한다. 이 화면이나 자료 묶음을 Wiki 입력으로 사용하지 않는다. 문항 검수와 법규 스냅샷 활성화는 별도다. 출처: [검수 화면 운영](../../docs/review_workbench.md).

등록 전 사전 점검은 읽기 전용으로 현재 리비전·근거와 제출 형식을 확인하고 예상 등록 상태를 보여준다. 점검 통과는 사람 검수의 진위나 법률 해석의 정합성을 보증하지 않으며 실제 등록 시 다시 검사한다. 출처: [검수 화면 운영](../../docs/review_workbench.md).
