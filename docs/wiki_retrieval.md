# Wiki 검색 보조의 오프라인 실험

2026-09-23. 후속 범위는 원문 검색과 Wiki 후보 확장을 비교할 실행 경로다. **서비스 질의 API·임베딩 검색·LLM 답변 생성·법규 요약 자동 생성은 이 작업에 포함하지 않았다.** S2-W01의 준비 작업이며 S2-01·03·06 또는 G1/G2 완료를 뜻하지 않는다.

## 구현한 경로

1. PostgreSQL의 고정한 스냅샷과 검수 상태를 `REPEATABLE READ READ ONLY` 트랜잭션으로 읽는다. 활성 스냅샷이 없거나 명시한 스냅샷이 미검수이면 종료 코드 2로 중단한다. 미검수 자료를 허용하는 옵션은 없다.
2. 지원 조문·기간·시점 검수자를 확인한다. 원본 HTML의 바이트 해시를 검사하고 다시 파싱하여 저장 조문의 본문·위치·부모·조 번호와 대조한다. 후보 스냅샷을 활성화하거나 DB를 수정하지 않는다.
3. 기준일·문서 종류로 후보를 제한한다. 법규명·조 번호 필터를 지원하며 `제1조`가 `제10조`를 찾지 않게 한다. 적용 종료 경계는 제외하고, 종료일이 없더라도 스냅샷의 검증된 기간을 넘지 않는다. 경과조치에 추가 사실관계가 필요한 조문은 후보에서 제외한다.
4. 원문 BM25와 검수된 Wiki 페이지 검색을 각각 수행한다. Wiki가 제안한 ID를 현재 원문으로 다시 해석하고 순위 기반 결합(RRF)을 적용한다. 결과에는 원문·버전·출처 URL·원문 위치를 보존하며 Wiki 요약 문장은 입력 근거로 넘기지 않는다.
5. 부모·검증된 관련 조문을 연결한다. 미확보·기간 밖 참조는 미해결로 표시한다. 문자 예산을 넘으면 조문 전체를 제외하고 ID를 남겨 단서·예외가 잘리지 않게 한다. 이는 토크나이저 기반 모델 입력 예산 구현은 아니다.
6. Wiki 스냅샷/내용 해시 변경, 허위 ID, 변경된 발췌, 시점 미검수, 미해결 문맥, 검수 후 수정된 페이지를 제외한다. Wiki 파일 없음·손상·참조 실패 때는 원문 검색을 유지한다. DB·원문 무결성 실패는 원문 검색 성공으로 위장하지 않고 실험을 중단한다.

Wiki 검수는 페이지 내용 해시에 연결한다. 네 항목(존재·의미·시점·완전성) 모두 `pass`여야 하며 개발자 검수에는 공식 교차 대조 기록이 필요하다. 이 파일 계약은 검수자 신원 인증 시스템이 아니며 AI가 실제 검수 기록을 대신 작성할 수 없다.

전체 말뭉치 내용 해시를 Wiki 빌드와 연결하는 보수적인 방식이다. 한 원문·검수 상태라도 바뀌면 기존 빌드 전체를 제외한다. 페이지별 증분 재생성과 서비스의 원자적 활성화는 후속 작업이다.

## 검색 설정

[configs/wiki_retrieval.json](../configs/wiki_retrieval.json)에 토큰화 버전, BM25 `k1`·`b`, RRF 상수, 검색 개수, Wiki 페이지 개수, 문맥 문자 예산을 고정한다. 설정과 말뭉치·Wiki 빌드의 해시를 보고서에 남긴다.

BM25는 단어 빈도와 문서 길이를 반영하는 검색 방식이다. [Stanford IR 교재](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)의 설명을 참고했고, 구현은 `log(1 + (N-df+0.5)/(df+0.5))`의 양수 IDF를 사용한다. 한국어 조사에 일부 대응하려고 NFKC 정규화 단어와 한글 2음절 조각을 함께 사용한다. 형태소 분석이나 학습된 의미 검색이 아니며, 한국어 법규 검색 성능이 입증된 설정으로 해석하지 않는다.

## 명령

저장소 루트에서 실행한다. DB 설정은 기존 `.env`를 사용하고 비밀값은 출력하지 않는다.

```powershell
uv run --frozen python scripts/experiment_wiki.py status
```

상태 명령은 활성 스냅샷 수·검수 상태별 개수만 읽는다. 확인 당시 활성 스냅샷 0개, 후보 스냅샷 1개(`pending`), 조문 2,035개(`unreviewed`), 개발 문항 50개(`draft`)여서 실제 비교는 중단된다. `status`가 0으로 종료하는 것은 상태 조회 성공이며 데이터 준비 완료를 뜻하지 않는다.

아래 명령은 검증된 스냅샷과 검수된 개발 문항이 준비된 후 사용한다. `--snapshot`을 생략하면 활성 스냅샷을 한 번 선택한다. 지정할 때도 검증 조건은 동일하다.

```powershell
# 원문 제목과 근거 참조만 내보낸다. summary는 빈 값, review는 null이다.
uv run --frozen python scripts/experiment_wiki.py draft --output artifacts/legal-wiki/draft-v1.json

# 원문을 대조해 summary를 작성한 뒤 검수 대상 페이지 해시를 확인한다.
uv run --frozen python scripts/experiment_wiki.py inspect --wiki artifacts/legal-wiki/draft-v1.json

# 실제 dataset_id와 검수한 Wiki 파일을 지정한다.
uv run --frozen python scripts/experiment_wiki.py compare --dataset YOUR_DEV_DATASET_ID --wiki artifacts/legal-wiki/reviewed-v1.json --output artifacts/wiki-retrieval/comparison-v1.json
```

출력은 지정한 `artifacts` 하위 JSON에만 저장하고 기존 파일을 덮어쓰지 않는다. Wiki 입력은 `artifacts/legal-wiki` 아래 명시한 JSON 한 개로 제한한다. `wiki/` 프로젝트 문서나 평가 폴더를 자동으로 수집하지 않는다. 유효한 검수 파일이 없으면 비교 보고서의 `wiki_status`에 `unavailable` 또는 `no_usable_match`가 표시되므로 이를 Wiki 효과 평가 완료로 해석하지 않는다.

페이지의 `review`를 작성할 때는 `inspect`가 출력한 `page_sha256`, 실제 검수자·역할·방법·시간대 포함 시각·사람 확인 표시·네 항목 결과와 이유·공식 대조 기록을 넣는다. 필드 계약은 [CandidatePage와 PageReview](../src/finreg/wiki_retrieval.py)에 있다. LLM으로 요약을 작성하면 빌드의 `generator`에 실제 모델 ID·리비전·프롬프트 버전·생성 설정을 기록한다. 템플릿의 `model_id=none`을 모델 실행 이력으로 사용하지 않는다. 내용·참조를 변경하면 다시 대조하고 검수한다.

`compare`는 DB에서 `split='dev' AND review_status='reviewed'`인 문항만 읽고, `answered` 문항의 원문 Recall@k·실제 문맥 포함률·검색 지연·문자 수를 비교한다. 추가 질문·보류 문항은 제외 개수로 남긴다. 최종 평가 질문·정답·해설을 읽는 옵션은 없다. 보고서는 문항 ID·리비전·해시·근거 ID를 포함하며 질문·정답·원문 본문을 저장하지 않는다.

## 검증과 남은 작업

최종 검사: DB 통합 테스트를 포함해 65개 통과, 건너뛰기 0개, 기존 의존성 경고 2개다. 린트와 프로젝트 Wiki 검사도 통과했다. 실제 미검수 말뭉치에서 `draft` 명령이 종료 코드 2로 중단되고 파일을 생성하지 않는지 확인했다. [실행 기록](reports/wiki-retrieval-20260923.json)에 결과와 미실행 범위를 남겼다.

가상 규정 테스트로 후보 추가 후 원문 반환, 버전·해시·검수 변경, 문서 종류·조 번호·시행일 경계, 경과조치 제외, 미해결 참조, 문맥 예산, Wiki 실패 시 원문 검색 유지, 원문 파싱 재대조를 검사한다. 테스트 DB에서는 격리된 스키마에 가상 자료를 만들고 롤백한다. 실제 말뭉치 검수 상태는 바꾸지 않는다.

서비스 채택에는 [LLM Wiki 도입 기준](llm_wiki.md)의 실제 개발 비교가 필요하다. 먼저 원문·부칙·별표·시점과 개발 정답을 사람 검수하고 지원 범위를 확정해야 한다. 이어 임베딩 결합 검색·인용 검증·RAG 기준선을 완성하고, 동일 모델·문맥 예산에서 답변 정합성·인용·시점·보류·토큰·갱신 비용을 비교한다. 이 도구의 검색 점수를 법규 답변 정확도로 보고하지 않는다.
