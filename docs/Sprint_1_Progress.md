## 환경 구성 검증

- 기능 브랜치: `feat/project-setup`.
- `ruff check`: 통과.
- 테스트: 4개 통과. 실제 `finreg_test` PostgreSQL 연결 검사를 포함한다.
- 실제 Uvicorn 프로세스에서 `/health/ready`: HTTP 200, `database = available`. 확인용 API 프로세스는 종료했다.
- DB 미설정·장애는 503으로 구분하며 예외 응답에 접속 비밀값이 나오지 않는지 확인했다.
- 테스트 도구에서 Starlette의 httpx 및 AnyIO API 사용 중단 예정 경고 2개가 발생했다. 기능 테스트 실패는 아니며 잠금 파일에 현재 조합을 기록했다.
- DB 초기화 중 한글 경로·Windows 출력 핸들 문제가 있었다. 임시 드라이브 별칭과 파일 출력으로 수정하고 DB 생성·재시작·실제 연결을 검증했다.

G1은 아직 통과하지 않았다. API/DB 환경 준비와 법규 데이터·모델 준비를 구분한다.

## 수집·데이터 모델 검증

- 기능 브랜치: `feat/corpus-ingestion` (`feat/project-setup`의 환경 구성 커밋을 포함).
- 실제 수집본: 3개 버전, 2,035개 구조 단위, 미해결 참조 후보 4,766개, PDF 11개.
- API 기반 검사와 원문 파싱·멱등 등록·원문 변조 거절·미검수 활성화 거절·사람 기록 없는 시점 검증 거절·마이그레이션 재실행 검사를 수행했다.
- 법규 의미·적용 판단의 검수 통과 수치는 없으며 수집본을 정답 데이터로 사용하지 않는다.
- 수집 기능 완료 시점 테스트 11개 통과. 검증 범위를 벗어난 새 스냅샷의 활성화가 실패해도 기존 활성 포인터가 유지되는지 가상 자료로 확인했다. 확보한 실제 원문의 문서 ID·버전·공포일·시행일도 수집 설정과 다시 대조했다.

## 초기 문항·검수 구조 검증

- 기능 브랜치: `feat/dataset-review` (`feat/corpus-ingestion`의 수집 기능을 포함).
- 실제 DB에 초기 개발 문항 20건을 등록했다. `draft` 20건, 사람 검수 로그 0건, 외부 검토 0건이다. 이 숫자는 생성 시점 상태다.
- 네 항목의 결과·사유, 검수자/역할·실제 검수 일시·방법·소요 시간, 공식 교차 대조 자료, 정확한 문항 리비전/내용 해시와 근거를 기록할 수 있다.
- 테스트 18개 통과. 허위 발췌·일부 근거만 검수·오래된 리비전 검수·이력 덮어쓰기·그룹 교차 분할·test 개발용 내보내기 차단, 수정 후 draft 복귀, 개발자/외부 검토 구분을 확인했다. 테스트의 검수자는 가상 인물이며 실제 문항을 reviewed로 만들지 않았다.
- 실제 20건의 파일 해시와 DB 근거 발췌가 일치함을 확인했다. CLI의 빈 체크리스트 생성, reviewed 0건 내보내기 거절, 기존 검수 폴더 덮어쓰기 거절도 확인했다.
- [검수 방법](dataset_review.md)을 따라 사람이 검토해야 한다. 생성 스크립트 실행 시간과 사람의 작성·원문 대조·수정 시간을 구분하며, 미실측 사람 시간은 null로 남겼다.
- 기반 모델 실행과 S1-08의 개발 50건·최종 100건 준비는 아직 남아 있다. 최종 평가셋 봉인은 수행하지 않았다.
